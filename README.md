# fable5-1-deepthink

Claude Code / Codex / Antigravity(旧 Gemini CLI、コマンドは `agy`)の3つのエージェントCLIで共通に使える「深い思考プロトコル」スキルです。Fable 5.1 クラスのモデルが示す長期タスク遂行、前提の明文化、複数仮説の比較、自己批判、道具での裏取り、スコープ維持、確信度の明示を、どのモデルでも再現できるよう手順化しています。トークン消費が増えすぎないよう、タスクの難易度に応じて手順の重さを自動で切り替える設計です。

本スキルは、[fable5-deepthink](https://github.com/YusukeKimata-Moo/fable5-deepthink) を基に、Fable 5.1の公式プロンプティング指針に合わせて派生・拡張したものです。元スキルの中核プロトコルを維持しつつ、長期作業の進捗通知、最新情報の検索、独立ツール呼び出しの一括実行、依頼範囲の維持、局所編集、コンテキスト圧縮への耐性を追加しています。

インストーラはパスをハードコードしません。リポジトリはどこにクローンしても、実行したマシンのホームディレクトリを基準に自動でセットアップされます。

## インストール

このスキルディレクトリを任意の場所に配置し、ディレクトリ内で次を実行します。

```bash
python scripts/setup_agents.py
```

これだけで、導入済みのエージェントすべてに対して以下を自動登録します(未導入のエージェントは `SKIPPED` として飛ばします):

- スキル本体の登録(各エージェントの skills ディレクトリへリンク、Antigravity は skills.json へ登録)
- 自動発動の保険となるグローバル指示行(Codex / Antigravity の AGENTS.md)

冪等なので、何度実行しても安全です(既存ファイルは上書きしません)。

> Antigravity 連携を最もきれいに保つには、`~/.agents/skills/fable5-1-deepthink` に配置するのが理想です。インストーラはスキルの親ディレクトリを skills.json に登録するため、その親が他スキルと共用の `~/.agents/skills` になります。

### 状態確認 / 再登録 / アンインストール

```bash
python scripts/setup_agents.py --check      # 状態だけ表示(変更しない)
python scripts/setup_agents.py              # 足りないものを作成(再登録・修復)
python scripts/setup_agents.py --uninstall  # 登録したものを削除(スキル本体は残す)
```

`--check` は5項目(スキルリンク×2、Antigravity skills.json、グローバル指示行×2)を `OK` / `MISSING` / `SKIPPED` / `ERROR` で表示します。

## 使い方

### 自動発動(何もしなくてよい)

複雑なデバッグ、原因不明の不具合調査、設計判断、失敗が続いているタスクなどでは、各エージェントがこのスキルを自動的に読み込んで手順に従います。単純な質問や小さな編集では発動しません(これが仕様です。無駄なトークンを使わないため)。

インストーラが Codex と Antigravity の AGENTS.md に「複雑なタスクではこの SKILL.md を読んで従う」という1行を登録するため、スキル自動発動の実装品質に関係なく発動を後押しします。

### 明示的に起動する

スキルを名前で直接呼び出します。

| CLI | 起動方法 |
|---|---|
| Claude Code | `/fable5-1-deepthink <タスク>` |
| Codex | `$fable5-1-deepthink <タスク>`(`/skills` で一覧表示) |
| Antigravity (agy) | 自動発動、または「deepthink プロトコルで」とプロンプトに記載 |

明示起動した場合、エージェントは最低でも T1(標準プロトコル)以上で動きます。

## 仕組み(3段階トリアージ)

エージェントはまずタスクを3段階に分類し、必要な分だけトークンを使います。

| 階層 | 判定条件(機械的なYes/No) | 動作 |
|---|---|---|
| **T0 直答** | すべて満たす: 1ステップで解決/完全に可逆/未検証の前提が不要 | プロトコルを使わず普通に回答(追加消費ゼロ) |
| **T1 標準** | T0でもT2でもないすべて | インライン手順: ゴール再定義 → 仮説2〜3個 → 安価な検証 → 自己批判1回 → 出口ゲート → 結論先行で回答 |
| **T2 深思考** | 1つでも該当: サプライズ2回/既に2回以上修正が失敗している問題/取り消し困難な操作(削除・マイグレーション・本番)/最初の検証後も原因不明/3ファイル以上に変更/ユーザーが明示要求 | `references/deep-mode.md` の完全手順 + 外部スクラッチパッド |

**サプライズカウンター**: 検証結果が予想と食い違うたびに +1 され、2回で自動的に T2 へ昇格します。「これは難しいタスクか?」という主観判断に頼らず、証拠ベースで深思考モードに入る仕組みです。エージェントは階層を宣言するとき理由も1行添えるので、判定ミスにはすぐ気づけます。

### T2 のスクラッチパッドとは

思考の浅いモデルでも深く考えられるようにする中核の仕組みです。仮説・事実・未検証の前提を作業ディレクトリの `.deepthink/thinking.md` に書き出し、判断のたびに読み直します。トークン節約のため:

- **60行上限**、超えたら圧縮
- **追記ではなく上書き**(履歴は残さない。棄却した仮説は理由1行だけ)
- 解決したらファイルは削除

エージェントが自分で作りますが、手動で用意する場合は(スキルディレクトリ内で):

```
python scripts/new_scratchpad.py            # カレントディレクトリに作成
python scripts/new_scratchpad.py --dir 対象パス
```

## トークン消費を抑える仕掛け(全階層共通)

- コードは `パス:行番号` で参照し、既に見たコードを再引用しない
- 自己批判は最大2パスまで。新しい発見がなくなったら即終了
- 読み込み済みファイルの再読込、合格済みチェックの再実行を禁止
- 調査の打ち切り基準あり(2回連続で進展がなければ、現時点の最善解+限界を明示して終了)

## Fable 5.1で追加した規律

- 長いツール処理では、思考過程を開示せず、開始時と節目に短い進捗を伝える
- 最新情報や変化の速い固有名詞は、記憶に頼らず検索して確認する
- 独立した確認は可能な範囲でまとめて実行する
- 依頼範囲外の修正・最適化・過剰なテスト追加を避ける
- 小さな変更はファイル全体を書き直さず、局所編集する
- 圧縮後も目的、制約、決定、失敗理由、現在地を保持する

T0/T1/T2は作業手順の深さであり、Claude APIの `effort` 設定とは別概念です。effort値を固定対応させず、各環境の既定値から実測に基づいて調整します。

設計根拠: [Prompting Claude Fable 5.1](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1)、[Migrating to Claude Fable 5.1](https://platform.claude.com/docs/en/models/fable-5-1/migration-guide)。

## プロトコルの改良

`SKILL.md`(トリアージと標準手順)と `references/deep-mode.md`(深思考の詳細手順)を直接編集してください。各エージェントのスキルはこのリポジトリへのリンクなので、**編集すれば全エージェントに同時に反映されます**。

## フォルダ構成

```
fable5-1-deepthink/
├── SKILL.md                  # エージェントが読む本体(トリアージ+T1手順+トークン規律)
├── references/
│   └── deep-mode.md          # T2深思考モードの完全手順(必要時のみ読み込まれる)
├── scripts/
│   ├── new_scratchpad.py     # スクラッチパッド生成
│   └── setup_agents.py       # インストーラ(登録・検証・アンインストール)
└── README.md                 # このファイル(人間向け)
```
